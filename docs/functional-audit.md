# Functional Audit: NotDjinni

Дата аудита: 2026-04-08

## Кратко

`NotDjinni` — Android-приложение для двух ролей:

- `Seeker` (соискатель): создаёт профиль, ищет вакансии, просматривает детали вакансий, откликается, отслеживает свои отклики.
- `Employer` (работодатель): создаёт профиль работодателя, привязывается к компании, публикует вакансии, просматривает отклики и меняет их статус.

Приложение использует токеновую сессию, стартует со `Splash`, после чего ведёт либо в авторизацию, либо в выбор роли. Выбор роли сохраняется локально, а дальнейший маршрут зависит от того, существует ли профиль для этой роли.

## Роли и доступ

### 1. Splash и сессия

- При запуске приложение валидирует токен через backend.
- Если токен валиден, пользователь попадает на экран выбора роли.
- Если токен невалиден или отсутствует, пользователь попадает на экран авторизации.
- В `DataStore` сохраняются:
  - access token
  - refresh token
  - текущая роль

### 2. Авторизация и регистрация

Подтверждённый функционал:

- Вход по `email + password`.
- Регистрация по `name + email + password`.
- После успешного входа или регистрации access/refresh token сохраняются локально.
- После успешной авторизации пользователь переводится на выбор роли.
- Ошибки авторизации показываются в UI.

Не найдено в пользовательском потоке:

- отдельный экран выхода из аккаунта;
- восстановление пароля;
- подтверждение email;
- редактирование учётной записи.

### 3. Выбор роли

Подтверждённый функционал:

- Пользователь может выбрать одну из двух ролей: `SEEKER` или `EMPLOYER`.
- После выбора роль сохраняется в `SessionDataStore`.
- Для каждой роли приложение проверяет наличие профиля:
  - если профиль уже существует, открывается главная соответствующей роли;
  - если профиля нет, открывается экран создания профиля.

## Функционал Seeker

### 1. Создание профиля соискателя

Подтверждённый функционал:

- Создание профиля со следующими полями:
  - speciality;
  - desired salary;
  - years of experience;
  - about me;
  - job category;
  - список work experience.
- Для опыта работы поддерживаются поля:
  - position;
  - company name;
  - description;
  - start date;
  - end date.
- Есть клиентская валидация обязательных полей.
- Есть выбор категории вакансий.
- Можно добавить несколько записей опыта работы.
- После успешного создания профиля пользователь переводится на главный экран `Seeker`.

Подтверждённые категории:

- `SOFTWARE_DEV`
- `DATA_SCIENCE`
- `DEVOPS`
- `QA`
- `PRODUCT_MGMT`
- `DESIGN`
- `MARKETING`
- `SALES`
- `HR`
- `FINANCE`
- `OPERATIONS`
- `SUPPORT`

### 2. Главный экран Seeker

Подтверждённый функционал:

- Главный экран умеет показывать вакансии в двух вкладках:
  - `All`
  - `Recommended`
- Для списка вакансий есть поиск по строке.
- Поиск работает с debounce.
- Для вкладки `All` вакансии грузятся из общего vacancy endpoint.
- Для вкладки `Recommended` вакансии грузятся из `SeekerRepository.getRecommendedVacancies(...)`.
- С главного экрана можно:
  - открыть детали вакансии;
  - перейти к своему профилю;
  - перейти к списку своих откликов.

Карточка вакансии на главном экране показывает:

- title;
- company name;
- salary range;
- required experience;
- employment type.

### 3. Детали вакансии для Seeker

Подтверждённый функционал:

- Загрузка детальной информации о вакансии по `vacancyId`.
- Отображение:
  - title;
  - company name;
  - company description;
  - description;
  - salary range;
  - employment type;
  - required experience;
  - category;
  - posted date.
- При открытии дополнительно проверяется:
  - профиль соискателя;
  - факт уже отправленного отклика.
- Приложение вычисляет eligibility к отклику:
  - хватает ли опыта;
  - укладывается ли вакансия в salary expectation;
  - нужно ли показать предупреждение о зарплате.
- Если опыта недостаточно, отклик недоступен.
- Если salary ниже ожиданий, это не блокирует отклик, но показывает warning.
- Если пользователь уже откликался, повторный отклик блокируется.
- Отклик отправляется через bottom sheet.
- Cover letter поддерживается и является опциональным.

### 4. Отклики соискателя

Подтверждённый функционал:

- Экран списка своих откликов загружает отклики текущего соискателя.
- Из списка можно открыть детали конкретного отклика.
- Экран деталей отклика загружает полную информацию по `applicationId`.

Подтверждённые статусы откликов в доменной модели:

- `APPLIED`
- `REVIEWING`
- `INTERVIEW`
- `TEST_TASK`
- `OFFER`
- `HIRED`
- `REJECTED`
- `WITHDRAWN`

### 5. Профиль соискателя

Подтверждённый функционал:

- Экран профиля одновременно загружает:
  - базовые данные пользователя;
  - профиль соискателя.
- При ошибке загрузки есть error state.
- Из профиля можно перейти обратно на выбор роли.

Важно:

- Переход “сменить роль” ведёт на экран выбора роли, но не является logout.

## Функционал Employer

### 1. Создание профиля работодателя

Подтверждённый функционал:

- Создание профиля работодателя требует:
  - выбрать компанию;
  - указать свою роль в компании.
- Компании ищутся через backend search endpoint.
- Поиск компаний работает с debounce.
- При открытии выбора компании сначала загружается initial list.
- После успешного создания профиля пользователь переводится на главный экран `Employer`.

### 2. Главный экран Employer

Подтверждённый функционал:

- Главный экран работодателя показывает список вакансий работодателя.
- С экрана можно:
  - открыть детали вакансии;
  - перейти в свой профиль;
  - перейти к созданию вакансии.

Карточка вакансии показывает:

- title;
- company name;
- salary range;
- required experience;
- employment type.

### 3. Создание вакансии

Подтверждённый функционал:

- Работодатель может создать вакансию со следующими полями:
  - title;
  - description;
  - salary min;
  - salary max;
  - min experience years;
  - employment type;
  - category.
- Есть клиентская валидация:
  - все обязательные поля должны быть заполнены;
  - числовые поля должны корректно парситься.
- После успешного создания выполняется переход на экран деталей созданной вакансии.

Подтверждённые типы занятости:

- `FULL_TIME`
- `PART_TIME`
- `CONTRACT`
- `TEMPORARY`
- `INTERNSHIP`
- `FREELANCE`

По коду vacancy создаётся со статусом `ACTIVE`.

### 4. Детали вакансии работодателя

Подтверждённый функционал:

- Экран деталей вакансии загружает вакансию по `vacancyId`.
- Показывает:
  - title;
  - description;
  - salary range;
  - employment type;
  - required experience;
  - category;
  - status;
  - posted date;
  - updated date.
- Из деталей вакансии можно перейти к откликам по этой вакансии.

Подтверждённые статусы вакансии в модели:

- `DRAFT`
- `ACTIVE`
- `PAUSED`
- `CLOSED`
- `EXPIRED`

### 5. Отклики по вакансии

Подтверждённый функционал:

- Работодатель может загрузить список откликов по конкретной вакансии.
- Для каждого отклика показываются:
  - speciality кандидата;
  - experience years;
  - current status;
  - cover letter preview;
  - applied date.
- Из списка можно открыть детали отклика.

### 6. Детали отклика и управление статусом

Подтверждённый функционал:

- Работодатель может открыть детальный экран отклика.
- На экране доступны:
  - текущий статус;
  - данные кандидата;
  - данные вакансии;
  - cover letter;
  - applied date;
  - updated date.
- С экрана можно:
  - перейти к деталям вакансии;
  - открыть bottom sheet изменения статуса;
  - изменить статус отклика.
- После изменения статуса UI обновляется оптимистично.
- Если backend подтверждает обновление, показывается success snackbar.
- Если backend отклоняет обновление, экран перезагружает актуальные данные.

### 7. Профиль работодателя

Подтверждённый функционал:

- Экран профиля одновременно загружает:
  - базовые данные пользователя;
  - профиль работодателя.
- При ошибке загрузки есть error state.
- Из профиля можно перейти обратно на выбор роли.

Важно:

- Переход “сменить роль” не равен выходу из аккаунта.

## Ограничения и незавершённые сценарии

### 1. Экраны-заглушки

В коде есть маршруты/экраны, которые выглядят незавершёнными:

- `Seeker.AllVacancies`
- `Seeker.AppliedVacancies`
- `Employer.ViewProfile`

По этим частям видно:

- пустые `ViewModel` без бизнес-логики;
- пустой или почти пустой UI;
- package naming местами не совпадает с route/screen naming, что похоже на черновую или недоведённую реализацию.

Итог:

- сценарии формально присутствуют в навигации, но как пользовательский функционал считать их завершёнными нельзя.

### 2. Logout не выведен в пользовательский сценарий

- В data/network слоях `logout` реализован.
- В исследованном UI нет подтверждённого экрана или действия, через которое пользователь реально инициирует logout.

### 3. Нет редактирования сущностей

В исследованном коде не найден подтверждённый пользовательский функционал для:

- редактирования профиля seeker;
- редактирования профиля employer;
- редактирования вакансии;
- снятия/архивации вакансии;
- отзыва отклика соискателем;
- удаления отклика;
- удаления профиля;
- редактирования company данных.

### 4. Нет тестового покрытия

- В репозитории не найдены `app/src/test` или `app/src/androidTest` с тестами.
- Это не функциональная возможность приложения, но важное ограничение качества текущей реализации.
