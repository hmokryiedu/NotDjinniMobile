# Employer Vacancy Duplication

## Overview
Новая функция для employer: дубликация уже существующей вакансии.

Функция позволяет создать новую вакансию на основе существующей вакансии как template. Новая вакансия открывается в обычном flow создания вакансии, но с уже предзаполненными полями из выбранной вакансии.

## User Goal
Employer может быстро создать новую вакансию из уже существующей, не заполняя все поля вручную заново.

## Requested Behavior
- Добавить кнопку `Duplicate` на экран вакансии.
- Добавить кнопку `Duplicate` на экран employer, которому принадлежит вакансия.
- При нажатии на `Duplicate` пользователь переходит на создание новой вакансии.
- Экран создания новой вакансии должен быть предзаполнен данными из выбранной существующей вакансии.
- Все предзаполненные поля можно редактировать, менять и сохранять как при обычном создании вакансии.
- После создания вакансии flow должен продолжаться так же, как текущий flow создания вакансии.
- После нажатия `Save` и успешного создания вакансии экран создания вакансии должен быть убран из back stack, чтобы пользователь не мог вернуться на него назад.

## UI Notes
- Кнопка `Duplicate` должна быть представлена как icon button.
- Icon button должен находиться где-то в top bar, чтобы не захламлять другие части экрана.

## Implementation Notes From Source Text
- Новых backend endpoints не нужно.
- Можно использовать уже существующий экран создания вакансии, если он сможет подтягивать данные для предзаполнения.
- Альтернатива: создать отдельный экран рядом, чтобы не передавать большой scope данных через navigation.
- Нужно избежать передачи чрезмерно большого набора данных вакансии через navigation, если это будет проблемой.

## Backend Contract
Новых endpoints не требуется.

## Acceptance Criteria
- Employer видит icon button `Duplicate` в top bar на экране вакансии.
- Employer видит icon button `Duplicate` в top bar на экране employer, которому принадлежит вакансия.
- Нажатие `Duplicate` открывает создание новой вакансии.
- Поля создания вакансии предзаполнены данными из исходной вакансии.
- Предзаполненные поля остаются редактируемыми.
- Сохранение создает новую вакансию по существующему flow создания вакансии.
- После успешного сохранения пользователь не может вернуться назад на экран создания этой вакансии через back stack.
- Для функции не добавляются новые backend endpoints.
